ucf-esp

进程内·桥接 API
唯一实现“真·运行时读进程内存”的项目，对应路 A（bridge）。
读取对象UnityCrossFire.exe 的 GameAssembly（IL2CPP 运行时对象）
手段Frida 注入 ＋ frida-il2cpp-bridge：按类名/方法名调 API——Camera.get_main() → get_worldToCameraMatrix()/get_projectionMatrix()；GameManager.myPlayer 静态字段、get_instance() → allPlayers；玩家 get_transform().get_position()、get_team()、get_isDead()、healthData（ObscuredInt.InternalDecrypt() 解密）
产出每 1s send() 一帧 JSON：{w2c[16], proj[16], local, players[]}（列主序）
消费frida_host.py 收帧 → esp_core.py 投影 → overlay_tk 叠加层；--replay 走离线回放
验证replay.py ＋ sample_session.json 黄金样本断言（3 个 world→screen 点 ±1px）
边界注释明确“仅限自有授权单机游戏；勿用于联机或他人游戏”；开发期用关闭反作弊的构建

ac-esp

合成数据 mock
阶段二被“编译期合成帧”替代，不读任何进程。
读取对象无（不附加进程、不加载 DLL/驱动）
手段EntitySource 抽象，唯一实现 FixtureEntitySource::read_frame() 返回硬编码单位矩阵 ＋ 3 个实体（hp 100/75/0）
产出FrameSnapshot（view_matrix ＋ entities）
消费app.cpp 投影为矩形 ＋ 诊断输出；CTest 校验投影与失效实体过滤
边界README：“不实现进程附加、隐蔽加载或反检测逻辑”；数据源抽象留给日后替换

ue_pak_archive_lab

文件级读取
读的是磁盘归档，不是进程内存。
读取对象已授权本地 PAK 归档文件
手段文件 I/O：尾部 PakInfo（magic/version/SHA1/offset）→ 索引 → Entry 结构 → 0x79 XOR 解密 → zlib 解压 → 写盘
产出解包出的 UE 资产文件 / 重打包归档
验证SHA-256、大小、索引摘要前后对比
阶段二关系若宽泛理解为“按偏移把静态格式变可消费数据”，它是文件按偏移读结构；对象是文件非内存

network_auth_audit_lab

消息级读取
读的是协议消息，审计其健壮性。
读取对象samples/auth_trace.json 合成轨迹；127.0.0.1 回环 TCP
手段JSON 解析 ＋ RC4/MD5 codec ＋ 字段变异测试（mutation_test.py）
产出风险清单（静态密钥 / 缺 nonce / 响应未验签 / 会话未绑定，共 5 项）＋ 整改项
阶段二关系读“消息内容”而非内存；方向是协议风险审计（防御视角）

android_loader_forensics_lab

静态取证
从样本文件字节流里找嵌入载荷，不执行、不加载。
读取对象samples/synthetic_loader.bin
手段正则 7f454c46… 定位 hex 编码 ELF → 解码为静态副本 → 记录字节数 ＋ SHA-256
产出analysis_output/embedded_*.elf ＋ manifest.tsv
阶段二关系对应“载荷如何藏在样本里”的发现，非运行时内存；脚本无 subprocess/加载逻辑

kernel_memory_defense_lab

建模＋防御
把“读内存 / 隐藏模块”机制做成用户态合成模型，用于理解与检测。
读取对象samples/ 合成页表 / ABI 清单 / 可见性快照（fixture 强制 scope=synthetic-only）
手段page_table_model.py 四级页表 PGD→PUD→PMD→PTE 虚拟→物理翻译＋跨页只读；abi_router.py 路由；module_visibility_audit.py 模块链表/sysfs/设备节点/ioremap 调用者不一致检测
产出页表路径、物理地址、读取字节；4 个可见性检测信号（退出码 1）
阶段二关系从防御侧建模读内存机制；不打开 /dev/mem、不调 process_vm_readv、不加载驱动
与「三条路」的对应关系
路线仓库内实现情况说明
路 A · bridge（类名/方法名调 IL2CPP API） ✔ 已实现 ucf-esp / tools/frida_dump.js＋frida-il2cpp-bridge；可读性好、需打包，目标为自有单机游戏
路 B · script.json 偏移 ＋ Memory.read* ✘ 无实现 il2cpp_dump/script.json 仅作静态参考；frida_dump.js 全程走方法调用，未按偏移直读内存
路 C · 外部进程 ReadProcessMemory ✘ 无实现 仓库内不存在外部 RPM 读取器（ac-esp 明确不实现进程附加）
数据来源：仓库内各项目 README、AGENTS.md 与核心源码（ucf-esp/tools/frida_dump.js、frida_host.py、esp_core.py、replay.py；ac-esp/src/entity_source.cpp、app.cpp；ue_pak_archive_lab/src/game_for_peace_unpack.c；network_auth_audit_lab/*.py；android_loader_forensics_lab/extract_hex_elf.py；kernel_memory_defense_lab/*.py）。本图仅为仓库现状的机制归纳，非任何在线游戏客户端的行为描述。
