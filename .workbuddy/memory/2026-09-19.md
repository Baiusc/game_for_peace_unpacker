## 掉帧修复「没奏效」的第二轮：真凶是 bridge 调用本身（提交 7e51998）
- 用户复测：节流 Linecast 后**还是卡**。上一轮把 Linecast 当成真凶是错的。
- **量化手法（很好用）**：心跳 `[*] 已发送 N 帧` 的间隔写死 `REPORT_MS=5000`，
  两次报告之间只增长 ~26 帧 → **实际 ~5 FPS**（请求的是 8ms=125Hz），
  即单帧 `frameTick` 占 Unity 主线程 ~190ms。以后从日志就能反推真实 FPS，无需工具。
- 真凶（按量级）：
  1. **`obj.tryMethod(name, argc)` 每次都不便宜**：`Memory.allocUtf8String(名字)` +
     `classGetMethodFromName`（native 方法表查找）+ 命中后 `bind()` 造一个 Proxy。
     取帧是「每帧×每玩家(10)×每字段(≈10)」上千次 → 最大头。
  2. **骨骼**：19×`GetBoneTransform` + 19×坐标读，失败还兜底 `characterContainer.Find`
     （按名字递归搜 Transform 层级的字符串查找，最多 57 次/玩家）；实测 100% valid=false 纯浪费。
  3. `Physics.Linecast`（上轮已节流，量级小一档）。
- 修：
  - `callMethod` 两级缓存：`(类|名字|参数个数)` → 未绑定 Method；
    `(类|对象|名字|参数个数)` → 已绑定 Method。稳态只剩 Map.get + invoke。
  - **禁止缓存「对象地址 → 类」**：Unity 回收对象后地址复用会把新对象当旧类，
    调错方法可能踩野内存（AV）。每次现取 `obj.class`（一次 objectGetClass，便宜）即可，
    类链进 key，地址复用成别的类时自然 miss。测试已加 `CLASS_OF` 不得出现的断言钉住。
  - 骨骼 250ms 墙钟节流 + 按玩家缓存；`--no-bones` 可彻底关。
  - `INTERVAL_MS` 默认 8 → **33**（≈30Hz）：**采样间隔必须 ≥ 单帧真实耗时**，
    设小了不会更快，只会让主线程一直忙。
  - 新增帧内分段计时：心跳里多打一行 `perf:`（单帧/玩家/骨骼/遮挡/send/缓存命中/实际 FPS）。
- `frida_host.py`：`--interval` 默认 33；新增 `--no-bones` / `--bones-refresh-ms` / `--vis-refresh-ms`。
- **打包坑（记牢）**：esbuild `--platform=neutral` 默认 ASCII charset，会把源码里的中文
  转义成 `\uXXXX`，于是按中文锚点做的「源码与 bundle 是否同步」测试全失败
  （报 `bundle.js 缺少 level0 的锚点 'level0 心跳'`）。**打包必须带 `--charset=utf8`**：
  `esbuild frida_dump.js --bundle --format=iife --platform=neutral --charset=utf8 --outfile=frida_dump.bundle.js`
